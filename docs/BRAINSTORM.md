## 一、三个没说破的前提

README 的公式很漂亮，但真正决定这个系统成败的是公式背后三个隐含承诺：

1. **“厚度”必须是结构性的。** 如果 `Unit` 只是一段不断变长的摘要，那厚度是假的——LLM 的上下文永远等长，最后只是把 300 天压成 2000 字，人格反而越活越薄。真正的厚度得来自：有槽位的状态、有时序的记忆、有冲突的信念，以及“同一件事在不同日子被想起的方式不一样”。
2. **`∩` 是关键，也是全篇唯一没有定义的算子。** 环境和压缩都能靠 LLM 糊过去，“感知过滤器”糊不过去——它决定了这个系统是“日志生成器”还是“灵魂”。
3. **公式里的 Unit 只会感知，不会行动。** 它是一个纯粹的观察者：看世界、写日记、变厚。这是否是想要的？如果 Unit 能行动、世界能回应，那就是另一类系统了。这是一个必须选的岔路，后面细说。

## 二、五个可以深挖的核心问题

### 1. `∩` 到底是“筛选”还是“投影”？

“只截取与自己相关的那一小部分”听起来像 RAG 检索，但那是机器的逻辑，不是人的逻辑。人感知世界的方式更接近：

- **盲点**：不是没看到，而是“看见了但不当回事”。一个自卑的人会放大别人的一个眼神，却忽略十句夸奖。
- **投射**：把旧情绪安到新事件上。今天心情差，同一场雨就是“世界在针对我”；心情好，就是“浪漫”。
- **未完成事件优先**：人对“未了之事”的注意力是压倒性的。明天要面试，今天路过的一切都会被解读成和面试有关。
- **注意力预算是有限的**：一天只能真正在意 3～5 件事，在意了工作就在意不了朋友。这个“配额”本身就是人格。

换句话说，`∩` 更适合建模成一个**有偏的透镜**，输入是 Unit 的当前关切 + 情绪底色 + 未了之事，输出是“今天世界在它眼里长什么样”。这比相关度排序有意思得多。

### 2. `C`（压缩）的灵魂是**遗忘和失真**，不是总结

如果压缩是“准确提炼要点”，那 Unit 只是变聪明的数据库。能让它像生命的，是压缩**会出错**：

- 日记原文（`Diary`）永久封存、只写不读；Unit 平时只读“它记得的版本”。两者之间的差额，就是人格。
- 失真要有方向：痛苦的事细节模糊、情绪放大；平淡的日子整段坍缩成一句“那阵子没什么事”；重要的不是事实而是**事后叙述**。
- 分级压缩：情绪强度高的日子几乎不压（留下细节），重复的日子合并，少数事件变成“刻痕”永远不压且会污染后续所有解读。
- 压缩比可以随“心理年龄”变化——年轻时什么都记，老了只记得几个画面。

这也顺势解释了项目名：**如果 Unit 某天重新读到了自己从未被压缩的原始日记，它和“现在的自己”之间的裂缝，就是 Reconnect（重连）。** 这个名字在 README 里没解释，但可能它就是隐藏主线——需要确认这是否是本意。

### 3. 情绪需要一层底层介质

README 里提到“情绪变化”，但没有给它位置。如果情绪只是日记里的一句话，那它不会影响感知，系统就没有闭环。可以给 Unit 一个**内在天气**：

- 情绪是黏性的，会向基线衰减，也会被事件推高/压低。
- 情绪**反过来影响 `∩`**：低落时更容易注意负面信息，于是更低落——螺旋。
- 宏观世界和内在天气可以耦合（真实天气 → 心情底色），这是 README 例子里那个“台风天被淋湿”的诗意来源。

有了这层，`Unit_t` 就不只是记忆，而是“记忆 + 当前状态”，行为和感知才有因果链。

### 4. 世界需要一个“接触面”，而不只是一个事件列表

`MacroWorld` 直接变成“今天的热搜/天气”，Unit 会像个新闻播报员。更真实的路径是世界通过它的**生活接口**渗进来：

- 通勤路线、工位、手机信息流、家庭群、常去的店——每个接口是一层天然过滤器。
- 宏观新闻要以微观渠道抵达：“同事午饭时提了一嘴”，而不是直接给 Unit 看头条。
- 这引出一个很关键的东西：**固定 NPC 群**。3～10 个持续存在、各自有自己生活轨迹的角色（老板、室友、暧昧对象、母亲），能让 100 天的日记从“平行日记”变成“故事”。没有 NPC 的生命是没有牵连的。

### 5. 纯日更没有“弧”，会变成肥皂剧

每天独立采样小事件，30 天后读起来会重复、平、没有形状。真实人生的形状来自季节、项目、关系演进、失去。弧可以从哪来？至少四个来源可以选或者组合：

- 未了之事的自然发酵（悬而未决的面试、拖着没说的话）
- NPC 关系曲线（认识→亲近→冲突→和解）
- 真实宏观世界的戏剧性（现实新闻本身就是剧本）
- 一个隐形的“导演”层，维持张力（这个最像写作，最不像生命）

## 三、还能长出来的机制（点子池）

- **睡眠/梦**：每天结束做一次“夜间整合”，用有损+联想重组的方式把当天并入记忆，顺便生成一段梦。梦是压缩算子最诗意的输出。
- **多层时间尺度压缩**：日 → 周 → 月 → 年。周记是反思，月记是章节，年记是“时代”。像海马体→皮层。
- **自我叙事（self-model）单独维护**：Unit 对自己是谁的信念，也是被压缩出来的，而且**可以是错的**。身份是反身的。
- **未了之事清单**：带紧迫度的 open loops，天然驱动注意力和行为。
- **关系账本**：对每个 NPC 的信任/亏欠/心结，而不是一句“关系很好”。
- **命运轨迹的不可逆性**：某些选择一旦发生就不能回档（搬家、辞职、错过），让每条生命线独一无二。
- **多 Unit 社会**：`Maze` 里可以包含别的 Unit，宏观世界里有“别人的人生”。这会让公式需要一次 unit-to-unit 的 `∩`。
- **投喂模式**：把用户自己的真实日记喂进去，造一个“数字回声”——这是另一种产品，但很有吸引力。
- **回望/重连模式**：让 Unit 读自己的旧日记，发现自己记错了、变了、还是没变。
- **生活之书可视化**：事件溯源天然支持时间轴/关系网/生命回放，最后可以输出一本可读的“一生”。

## 四、系统可能的五种“形态”（选哪种决定一切）

1. **观察者**：一个只会感受和写日记的灵魂，没有行为。最接近 README 字面意思，最省钱，但可能最“闷”。
2. **行动者**：每天感知 → 决策 → 行动 → 世界回应，完整闭环。更像 agent，但会偏离“日记”的文学性。
3. **加速演化**：一年压缩到几分钟跑完，看人格漂移曲线，偏研究/实验。
4. **社会**：多个 Unit 同处一个 Maze，互相影响，偏涌现/群像。
5. **重连**：核心是“过去的自己 vs 现在”的对话，偏叙事/情感。

README 写的是 1，但 1 和 2 之间那条线值得亲口定一下。

## 五、技术与评估，先只点问题不点方案

- **事件溯源几乎是天然的**：`Diary` 只追加不修改，`Unit` 是从日志推导出来的投影——这正好对应公式的 `Σ` 和 `C`，还能换来回放、调试、重现某一天的确切 prompt。
- **可复现性**：同一个 seed 是否应该得到同一条命？研究需要，生命感不需要。可以做成“确定性世界 + 随机感知”。
- **成本直觉**：一天大概 3～5 次 LLM 调用（生成世界、感知+日记、压缩、可能的反思）。一年就是上千次，得想清楚“时间”是真实时间还是模拟时间。
- **怎么证明它活着**：盲读测试（能不能分辨第 5 天和第 200 天的日记）、遗忘测试（该记的记得吗、该忘的忘了吗）、人格漂移曲线、两个不同 `Personal` 的 Unit 是否会走出明显不同的路。
- **最常见的失败模式**：日记变成“今天天气很好，我感到平静”这种通用 LLM 腔；几十天后主题塌缩、重复；Unit 滑向单一情绪；以及“有日记但没有人生”。

## 六、几个名字/本体的小想法

`Unit / Maze / Diary / Personal` 这套命名很好，可以继续长：**Imprint（刻痕）、Dream（梦）、Open Loop（未了）、Cast（人影）、Weather（内在天气）、Echo（回声）**。它们不只是变量名，会决定这个项目的文学气质——建议给概念命名时把“可命名性”也当设计目标。

## 七、需要拍板的几个岔路（先不用回答，只是绕不过去）

1. 是要做**可读的生命故事**，还是**可信的状态机**？两者的取舍会贯穿始终。
2. **观察者还是行动者**？公式目前是前者。
3. **真实世界锚定**（真实日期/天气/新闻）还是**虚构世界**（自洽的城与人）？两者对“一天”的定义完全不同。
4. **单灵魂还是多灵魂**？
5. **用户有没有“命运”的介入权**——能不能干预、许愿、制造一次意外？
6. 最后、也是最想问的：**Reconnect 到底指什么？** 答案可能能反过来定义整个系统。

## 八、本体建模：统一底层逻辑（2026-11-16 续）

> 本节承接上文“事件是系统的原子”的讨论，记录“用本体（Ontology）统一世界、人格、事件、记忆的底层表示”这一方案，以及对它的评估。

### 8.1 提案

- 客观事实与人格等，都是在本体基础上扩展出来的集合。
- 事件由一组“主谓宾”三元组构成，例如：`我 打开 电脑`、`我 在家`、`现在是 晚上`。
- 客观事件不以个人意志转移；主观感知是 Unit 基于自身人格对客观事件的**投射**。
- 本体同时承担两个角色：承载混沌的世界模型，以及作为 Unit 与 Maze 之间的**桥梁**——以事件记录的形式充当接口。

### 8.2 成立的部分

1. **统一表示**：世界、人格、记忆、事件共用一套数据模型，diff / 查询 / 回放 / 聚合近乎免费。自由文本日志下“记录以后分析”半真半假，本体日志下才真正成立。
2. **客观/主观可退化为“同一存储的不同作用域”**：世界写客观三元组，Unit 有私有三元组（信念、记忆）并只读世界的过滤视图。`unit ∩ unit` = 同一存储、不同读视图。
3. **“本体是桥”的比喻成立**：Unit 与 Maze 的通信从“互相塞 prompt”变为“共享词汇表”。
4. **人格用插槽（底色/状态/结构）在本体中很自然**：它们是关于 Unit 的三元组，可读、可 diff、可审计。

### 8.3 必须修正的三处（倾向性意见）

1. **事件不是三元组集合，而是快照的差分。** `我 在家` 是状态（Holding），`现在是晚上` 是环境属性，`我 打开 电脑` 是事件（Occurrence）。三者混在一个扁平集合里，无法回答“什么变了”，也就没有状态转移。建议：
   - `Snapshot_t = 一组 Holding（带有效区间）`
   - `Event = Delta（新增/删除的 Holding）+ 元数据（时间、施事、因果父）`
   - `State' = apply(State, Delta)`
2. **事件不是二元关系，需要 n-ary。** 「我给他书」「我和小王在咖啡厅见面」无法用二元主谓宾无损表达。标准做法是把事件本身当作节点，参数用角色边挂上（Davidsonian event）。若坚持二元，至少要用角色命名的谓词（如 `给·theme`、`给·recipient`）并保留一个事件 ID。
3. **人格不可能全是本体。** 人格分两类：
   - **声明性**（可存为本体）：`她 害怕 被抛弃`、`她 重视 母亲`；
   - **程序性**（是算子，不是数据）：怎么歪着看、怎么遗忘、怎么自我维护。
   状态与信念 = 本体；观测/压缩/衰减 = 作用于本体的函数。

### 8.4 实操风险（按严重程度）

1. **本体漂移与同义词**：LLM 不会稳定复用谓词，第 100 天可能出现数十种“在家附近”的说法。需要开放世界假设、谓词规范化、策展/合并循环。
2. **实体消解**：老板 / 王总 / 那个男的 是否同一人。需要稳定实体 ID 与合并策略。
3. **双时态**：每个三元组需记录 valid time 与 asserted time，否则无法回答“第 47 天它相信什么”，回放与记忆失真都做不了。
4. **信念库 ≠ 事实库**：主观感知是变换（加重、删减、改写、推断），不是子集。每条主观三元组需 `来源 / 置信度 / 显著性 / 衰减`，并处理矛盾与真值维护；只做过滤会退回 RAG。
5. **表达力上限 = 日记上限**：三元组丢掉时态、语气、程度、不确定、反事实。建议“结构化骨架 + 非结构化质感”：本体决定“发生了什么”，事件上挂自由文本决定“感觉像什么”。

### 8.5 关于“本体概括混沌”的修正

本体是形式化，混沌是它的反面。本体提供语法，混沌以三种方式住在里面：生成时的随机性、缺失与未知（开放世界）、矛盾（不同来源 / 不同 Unit 的冲突三元组）。更准确的说法：**本体是语法，混沌是分布的形态；事件是句子，不是语法本身。**

另外，“客观”不等于“公共”：世界真值、公开记录（新闻、传言）、每个 Unit 的私有信念，是三层不是两层。中间层恰好是 `unit ∩ unit` 最有趣的地方——两个 Unit 读到同一条传闻，却形成不同信念。

### 8.6 中性总结

- **比自由文本强得多**；它把“以后分析”从愿望变成能力，并统一了客观/主观、unit∩unit、接口三件事。
- **但它不是“存事实”工程，而是“信念库”工程。** 难度从“怎么生成事件”转移到“怎么治理本体、怎么维护信念一致性”。
- 决定成败的不是事件怎么表示，而是几个不显眼的元数据：**有效时间、断言来源、置信度、显著性、因果父**。缺任何一个，本体都会在几十天后退化。

### 8.7 待续

作者对 8.3 的三处修正有不同意见（坚持三元组、认为人格可全部编码为本体、提出用实体间交互推断日记），其回应与评估见后续讨论。
